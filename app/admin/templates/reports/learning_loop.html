How to Use the Learning Loop

What is the Learning Loop?

The Learning Loop is how you make Jill better over time. Every call is automatically scored for quality (success, naturalness, repeated questions, filler phrases). This page shows you patterns across calls, lets you run automated tests, and tracks every prompt change so you can see what's working.

Weekly Workflow

  1. Check insights — Open this page on Monday. The stat cards show this week vs last week. Look for regressions (red deltas) and the alert cards below.
  2. Investigate flagged calls — Click "View All Calls" to open the Call Quality page. Filter to the assistant with issues and read the transcripts of failed calls.
  3. Identify the pattern — e.g. "users say 'half seven' and Jill doesn't understand", or "Jill asks for the site twice".
  4. Fix the prompt — Edit the assistant prompt in code (e.g. timesheet_prompt_v2.py).
  5. Push to VAPI — Run the update script with a summary:
    python scripts/update_timesheet_prompt.py --summary "Added half seven time parsing"
    This updates VAPI and records the change in the Prompt Changes log below.
  6. Run Evals — Click the "Run Evals" button to test all assistants against the eval suite (~60 seconds). Check that existing evals still pass and any new ones pass too.
  7. Monitor next week — The insights will automatically show whether quality improved after your change.

Page Sections Explained

Quality Insights

Stat cards comparing this period to the previous period. Success rate, naturalness score, and issue percentages. Alert cards highlight specific regressions or improvements. Recurring themes extract patterns from improvement notes.

Quality Timeline

30-day bar chart showing daily success rate. Green = 80%+, yellow = 50-79%, red = below 50%. Purple dots mark prompt changes, green/red dots mark eval runs. Hover bars for details.

Eval Suite

Run VAPI's automated eval tests against all assistants. Each eval simulates a call scenario and checks the outcome. Results show pass/fail per test with failure reasons. Run evals after every prompt change to catch regressions.

Prompt Changes

Log of every prompt update pushed to VAPI. Recorded automatically when you use the update scripts with --summary. Helps correlate quality changes with specific prompt edits.

When to Run Evals

  • After every prompt change — Verify the change didn't break existing flows
  • After adding a new eval — Confirm the new test passes
  • Weekly check-in — Baseline pass rate tracking
  • Before deploying — Sanity check that everything still works

What Are Evals?

Evals (evaluations) are automated test scenarios for your voice assistants. Think of them like unit tests for Jill's conversations. Each eval defines:

  • A scenario — a simulated caller with a specific goal (e.g. "Log a timesheet for Monday, 7am to 3pm at the Riverside site")
  • Success criteria — what Jill should do (e.g. correctly parse the times, confirm the site, save the entry)

VAPI runs the scenario as a real conversation against your assistant, then checks whether the success criteria were met. The result is pass or fail with a reason.

We currently have 13 evals: 5 for the Greeter (authentication flows, routing) and 8 for Timesheet (time parsing, site matching, multi-entry, edge cases). Each eval run takes about 60 seconds as VAPI simulates real calls.

Adding New Evals

When you find a recurring failure pattern through the Learning Loop:

  1. Go to the VAPI Dashboard
  2. Open the relevant assistant (e.g. JSMB-Jill-timesheet)
  3. Navigate to the Evals tab
  4. Create a new eval with a scenario that reproduces the failure
  5. Come back here and click "Run Evals" to verify it passes after your prompt fix

Good eval naming convention: assistant_specific_scenario — e.g. timesheet_half_seven_time_parsing
